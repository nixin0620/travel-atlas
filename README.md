# 旅迹 · Travel Atlas

一套可在本机运行的旅行应用，也可以作为 Codex skill 安装。把交通住宿、每日行程、攻略与 My Pick 放在一起，再用中国/世界足迹地图记录照片和回忆。

这份体验版来自正在使用的最新应用，包含简化后的设置入口、六种配色及整份备份功能。无需付费 AI API 即可启动。

## 用 Codex 开始（一句话）

把这句话发给 Codex：

> 安装并启动 <https://github.com/nixin0620/travel-atlas>，带我开始使用。

Codex 会读取仓库中的 skill，检查运行环境，并让你选择“先看示例旅行”或“开始自己的旅行”。已有数据会优先保留；无需再粘贴详细操作提示词。

示例体验包含西双版纳 → 普洱 → 玉溪 → 昆明的四城十天安排，住宿均标注为“示例住宿 · 未预订”。示例使用独立目录、端口和存储，不会点亮你的已去过足迹。个人模式从你提供的行程、攻略或备份开始。

已安装过的朋友可以说：“更新 travel-atlas skill，保留我的数据，带我体验新版启动流程。”更新 skill 不会自动替换已有应用目录；Codex 会先检查实际版本，必要时先备份再更新。

想直接做自己的旅行，也可以只说：

> 用 https://github.com/nixin0620/travel-atlas 帮我做贵州七日游，节奏轻松些。

skill 会指导 Codex 查证地点、准备有来源的实景图片，并写入现有城市、日期、My Pick 和地图日程。没有酒店或车票也能规划；日期未定时按 D1…Dn 展示。更新前的朋友需要同时检查应用目录版本，不能只替换 SKILL.md。

## 手动启动

安装 Python 3.10 或更新版本，下载仓库 ZIP 并解压，在仓库目录运行：

```sh
python3 scripts/start.py --workspace ./my-travel --port 8790 --open
```

Windows 可用 `py -3` 代替 `python3`。保持终端运行，浏览器打开 [http://127.0.0.1:8790/#route](http://127.0.0.1:8790/#route)。再次运行同一命令会复用工作目录，不覆盖已有文件。

首次个人数据为空。建议从「交通 & 住宿」录入一项安排，然后到每日行程查看联动；也可以直接点亮城市、添加回忆，或粘贴攻略正文整理 My Pick。

想先看有内容的示例，可另开终端运行：

```sh
python3 scripts/start.py --demo --open
```

默认使用 `travel-demo` 目录和 8791 端口。重复运行会保留示例中的修改；不要用示例目录保存个人旅行。示例的日期为演示日期，图片仍是插画，不包含作者的私人旅行照片。

## 作为 skill 安装

把仓库链接 https://github.com/nixin0620/travel-atlas 发给 Codex，并说：

> 安装并启动这个仓库的 travel-atlas，带我开始使用。

也可以将整个仓库文件夹命名为 `travel-atlas`，放入 `~/.agents/skills/`，再说：

> 使用 $travel-atlas 启动我的旅行应用。

请复制整个文件夹，不要只复制 `SKILL.md`。安装位置参见 [Codex 官方 skills 文档](https://developers.openai.com/codex/skills/)。

## 当前包含

- 交通住宿记录、每日日期切换、顺序与安排联动。
- 公开攻略链接/正文导入，地点比较、My Pick、地图添加和修改位置。
- 中国与世界足迹总览、心愿城市、照片回忆和足迹回放。
- 六种主题；统一的「设置 → 外观与配色 / 数据与备份」。
- 浏览器本地保存、完整导出、恢复前快照，最近五份快照保留。

## 使用边界

公开版没有作者的订单、旅行照片、已去过记录或 API 密钥。安装模板保留插画占位；个性化旅行由 Codex 按内容工作流调研和补充许可明确的实景图，不会通过重装取回作者私图。`scripts/build-trip.cjs` 将资料接入现有界面，不另建长文网页；它不是自动旅行数据库，内容质量仍需调研与浏览器验收。

地图默认使用现有 OpenStreetMap 路径；高德可选，需配置自己的 Key。地图、POI 和公开攻略读取需要联网，平台限制访问时可改为粘贴正文。长图 OCR 目前需要 macOS 和 Swift 工具；其他系统可使用基础功能。详细说明见 [运行与地图](references/runtime.md)。

数据保存在当前浏览器，清理浏览器前请通过设置备份。GitHub 仅承载代码；完整体验需要启动本地服务，并非打开仓库网页就能在线使用。

## 首版验证

已在 macOS 浏览器检查空数据启动、新增住宿、每日行程联动、刷新保存和备份下载。复用的地图与备份逻辑共有 51 项回归测试通过；安装 Node.js 后可运行 `node --test tests/*.test.cjs`。Node.js 18+ 用于内容编译和测试，单纯启动已有应用不需要它。

本次网络环境中地点搜索能够返回候选结果，OpenStreetMap 底图出现部分加载失败；尚未验证所有网络环境、Windows 和 Linux。地图候选需要自行核对，亦可配置自己的高德服务。

新版启动流程另有 6 项测试，覆盖示例隔离、重复启动、旧目录兼容及防覆盖：`python3 -m unittest discover -s tests -p 'test_start.py'`。已在浏览器验证示例四城十天、城市切换、添加日程事项及刷新保存；示例未写入已去过记录。

## 新目的地生成修复

补齐了计划日期、图片来源、地点与原生日程的共用数据入口；修正了封面强制占位和默认底图地址错误。生成器不会把菜名自动当作 POI，也不会生成虚构订单或到访。具体资料格式与验收见 [目的地内容工作流](references/create-trip.md)。

这是一套通用的目的地内容工作流，贵州只是验收样例。城市、国家、日期、照片和地点均从内容包读取，不需要为新目的地另写页面；各目的地的实际资料与图片仍须查证。

本次增加 14 项规划与内容绑定测试，合计 65 项 JavaScript 回归测试及 6 项启动测试通过。数据联动测试另覆盖成都—乐山—成都、跨年日期、京都/圣保罗/雷克雅未克、全角英文城市名、闰日及既有城市别名，检查原生日程、My Pick、地图关联和国家归属。在 macOS 浏览器用独立贵州验收数据检查了三城七天、三张实景图、原生卡片、日程编辑刷新、地图标点/底图与整份备份导出；备份中图片字节及地点关联均保留，没有写入订单或已去过记录。测试数据仅用于功能验收，不是完整的七日推荐攻略。未查证的地点位置保持待确认。
